# Stack conventions

Keep the codebase consistent between sessions. When unsure, match existing patterns rather
than introducing a new one.

## Layout

```
/cmd/server            main.go — wiring, config, graceful shutdown
/internal/http         handlers, middleware (auth, rbac, csrf, ratelimit, headers)
/internal/service      business logic (conflict checks, assignment rules)
/internal/repo         sqlc-generated code + thin wrappers
/internal/auth         sessions, argon2id, csrf
/internal/i18n         translation layer (en, lv, ru)
/web/templates         .templ files
/web/static            css (tailwind build), htmx, minimal js, PWA manifest
/db/migrations         golang-migrate .up/.down
/db/queries            .sql for sqlc
sqlc.yaml  Dockerfile  docker-compose.yml  Caddyfile  .env.example
```

Strict dependency direction: `http → service → repo`. Handlers never touch the DB directly;
services never import `net/http`.

## Go

- Go 1.22+. `gofmt`/`goimports` clean. No unused deps.
- **Errors:** wrap with context `fmt.Errorf("creating assignment: %w", err)`. Sentinel or
  typed errors for cases the caller branches on (e.g. `ErrTimeConflict`,
  `ErrNotFound`, `ErrForbidden`). Handlers map error types → HTTP status; never leak
  internal error text to the client (log detail, return a generic message).
- **Context:** first arg `ctx context.Context` through service and repo; honor cancellation;
  set timeouts on DB calls.
- **No global mutable state.** Dependencies passed explicitly (constructor structs).
- **Handlers** do: parse → validate → authorize (via middleware + ownership check) →
  call service → render/respond. Nothing else.
- Time is `time.Time` in UTC everywhere; format only at the view boundary.

## Data access

- **All queries in `/db/queries/*.sql`, generated by `sqlc`.** No hand-written SQL in Go,
  no query string concatenation — this is a security rule, not a style one.
- Repositories return domain structs, not raw DB rows, when it clarifies the boundary.
- Transactions for multi-statement invariants (create assignment + audit entry together).

## HTTP / middleware order

`recover → request-id → security-headers → rate-limit → session/auth → csrf → rbac → handler`.
Every non-GET requires a valid CSRF token. Every non-public route requires a session and a
role check.

## Frontend (templ + htmx + Tailwind)

- Server-rendered `templ`; auto-escaped output. Never inject unescaped user data.
- `htmx` for interactivity; keep custom JS minimal and CSP-friendly (no inline handlers that
  force an unsafe CSP). Prefer `hx-*` attributes + small progressive-enhancement scripts.
- Tailwind for styling; extract repeated patterns into templ components, not copy-paste.
- Driver view: mobile-first, works as a PWA (manifest + service worker for offline shell).
- Timeline: rows = buses, time on the x-axis, trip blocks positioned by time; must stay
  legible on a phone (horizontal scroll is acceptable).

## i18n

- **No hardcoded UI strings.** All copy goes through `/internal/i18n` with keys; provide
  `en`, `lv`, `ru`. Locale from user preference (fallback to `Accept-Language` → `en`).
- Dates/times/numbers formatted per locale at the view layer.

## Config & secrets

- All config from env (12-factor). Fail fast if a required var is missing.
- `.env` git-ignored; commit only `.env.example` with dummy values.

## Tests

- Table-driven tests. Cover conflict detection, RBAC boundaries, auth flows (see CLAUDE.md).
- Use a real Postgres in tests (testcontainers or a compose service), not mocks, for repo
  and constraint behavior — the `EXCLUDE` constraint must be exercised.

## Definition of done (code)

`gofmt` clean · builds · `go test ./...` green · `govulncheck` clean · `sqlc generate`
up to date · no secret/PII committed · matches this file's patterns.
